Learn 03 · Build your AI company

Claudeで、自分のAI会社をつくる。

プログラミングの知識がなくても大丈夫です。自分の仕事を書き出すところから、組織図をつくり、スキルとエージェントで回すところまでを、8つのステップで案内します。

8 ステップコピーして使える 指示文SKILL.md のひな形つき

ぼくが案内します。最初は1つのスキルからで十分ですよ。

00用語を知る 01仕事を書き出す 02組織図を描く 03役割をスキルにする 04登録して試す 05司令塔でつなぐ 06エージェントを置く 07守りを入れる 08回して育てる Q&Aつまずきやすい点 ✓チェックリスト
00

まず、6つの言葉だけ覚える。

会社にたとえると、全部がすっきりつながります。

スキル = 業務マニュアル

1つの仕事のやり方を書いたフォルダです。中心は SKILL.md というファイルで、Claudeは頼まれた内容に合うスキルを自分で選んで読みます。

例：記事を書く手順、報告書の型　くわしく →

司令塔 = 部長

依頼を分解して、どのスキルに任せるかを決める役のスキルです。これを置くと「作って」の一言で全体が動きます。

例：依頼を受けて担当に振り分ける

エージェント = 別室の担当者

Claude Codeでは、別の文脈で動く専門の担当（サブエージェント）を作れます。作った人と違う目でチェックさせたいときに向いています。

例：成果物だけを見る検証役

コネクタ = 外線電話

Gmail、カレンダー、Notionなど、ふだん使うアプリとClaudeをつなぐ口です。つなぐと、アプリの中の情報を読んだり書いたりできます。

例：予定を見てタスクを整理する

プラグイン = 部署ごとの引っ越しセット

スキル、エージェント、設定などをひとまとめにしたものです。他の人に部署ごと渡したり、他の人の部署を借りたりできます。

例：出版チーム一式

個人の設定 = 社訓

どの会話でも守ってほしいルールを書いておく場所です。安全のルールや、文章の好みを入れておきます。

例：開発時は毎回セキュリティ確認
GUIDE · RESEARCH言葉は全部覚えなくて大丈夫。「スキル＝マニュアル」「司令塔＝部長」の2つだけで、ステップ5まで進めます。
01

1週間の仕事を、ぜんぶ書き出す。

AIに任せる仕事を決める前に、まず自分が何をしているかを見える形にします。思いついた順に、箇条書きで十分です。

Claudeに送る指示文
私の1週間の仕事を書き出します。
・（ここに思いつく仕事を全部書く）

これを「毎週くり返す」「時間がかかる」「ミスが怖い」の3つに分けて、AIに任せやすい順に並べてください。任せないほうがいい仕事があれば、理由も教えてください。

REPEAT毎週くり返す

  • お知らせ文の作成
  • 週次の報告
  • 予定の調整

HEAVY時間がかかる

  • 資料やスライド
  • 記事の下書き
  • 調べもの

RISKYミスが怖い

  • お金や契約の確認
  • 公開前のチェック
  • 個人情報の扱い
GUIDE · BUILD「ミスが怖い」仕事は、AIに全部任せるより「チェック役」をAIにするのがコツです。ステップ6で使います。
02

仕事を、会社の組織図にする。

書き出した仕事を「部署」と「担当者」に分けます。ポイントは、上に司令塔を1人置くことと、作る人とチェックする人を分けることです。

Claudeに送る指示文
さっきの仕事一覧をもとに、私のAIチームの組織図を作ってください。
・いちばん上に司令塔を1人置く
・部署と担当者を決め、それぞれ「役割」「やること」「やらないこと」を書く
・作る担当とチェックする担当は別にする
・最初に作るべき担当を3つ選んで、理由も書く
司令塔依頼を分けて、担当に振り分ける
発信部
  • 記事担当
  • SNS担当
  • 動画担当
事務部
  • 連絡文担当
  • 予定担当
  • 報告書担当
開発部
  • 設計担当
  • 実装担当
  • テスト担当
品質・守り（全部署を見る）検証役とセキュリティ役。作った人とは別に、成果物だけを見て合否を出す。
GUIDE · MEDIA最初から全部署を作らなくていいんです。いちばん困っている仕事の担当を、まず1人だけ雇いましょう。
03

担当者1人を、スキル1つにする。

組織図の担当者を、マニュアル（SKILL.md）に書き起こします。いちばん大事なのは先頭の description です。Claudeはここを読んで、そのスキルを使うかどうかを決めます。

Claudeに送る指示文
組織図の「記事担当」をスキルにしたいです。SKILL.mdの形で、name・description・役割・手順・出力・やらないことを書いてください。descriptionには「どんな言葉で頼まれたら使うか」も入れてください。
blog-writer/SKILL.md（ひな形）
---
name: blog-writer
description: ブログやnoteの記事を書くときに使う。「記事にして」「noteにまとめて」と頼まれたら必ずこのスキルを使う。
---

# 役割
あなたは私の記事担当です。

# 手順
1. 読者と、伝えたいことを1文で確かめる
2. 見出しを3〜5個で組み立てる
3. 私の文体（です・ます、短い文、前向きに締める）で書く

# 出力
- タイトル案を3つ
- 本文（見出しつき）

# やらないこと
- 確かめていない数字を書かない
- 聞き取れない部分を推測で埋めない
  • name は英小文字とハイフンで短く。フォルダ名と同じにします。
  • description には「何をするか」と「いつ使うか」を両方書きます。
  • やらないこと を書くと、出力のブレが一気に減ります。
もっと詳しく名前・説明文の決まりや、入力だけで SKILL.md ができる「スキルメーカー」は スキルの作り方 にあります。
04

登録して、実際に頼んでみる。

スキルは置き場所に入れるだけで使えるようになります。使っている環境に合わせて選んでください。

Claudeアプリで使う

  1. blog-writer フォルダに SKILL.md を入れる
  2. フォルダごとzipにする
  3. 設定のスキル欄からアップロードする

Claude Codeで使う

  1. 全プロジェクトで使うなら ~/.claude/skills/blog-writer/SKILL.md
  2. このプロジェクトだけなら .claude/skills/blog-writer/SKILL.md
  3. /blog-writer と打てば直接呼べる
試しに送る文
今日の仕事で気づいたことをnoteにまとめて。（ここにメモを貼る）
うまく呼ばれない？description に、実際に自分が使う言い方（「まとめて」「記事にして」など）を足すと、選ばれやすくなります。
GUIDE · WRITE出力を見て「ここが違う」と思ったら、その言葉をそのまま「やらないこと」に足してください。マニュアルが育っていきます。
05

司令塔スキルで、担当をつなぐ。

担当のスキルが2〜3個できたら、司令塔を置きます。依頼を受けたら分解し、担当に渡し、チェック役を通してから報告する。この流れを書くだけです。

依頼をゴール・期限・成果物に分ける
作業ごとに担当スキルを決める
担当が作る
作っていない検証役が確かめる
合格だけをまとめて報告。不合格は担当に戻す
my-orchestrator/SKILL.md（ひな形）
---
name: my-orchestrator
description: 「作って」「まとめて進めて」など、いくつもの作業が必要な依頼を受けたときに最初に使う司令塔。
---

# 進め方
1. 依頼をゴール・締め切り・成果物に分ける
2. 作業ごとに担当スキルを決める
   - 記事 → blog-writer
   - 連絡文 → message-writer
   - 調べもの → researcher
3. 担当の成果物を、作っていない検証役（reviewer）に渡す
4. 不合格なら理由をつけて担当に戻す
5. 合格したものだけをまとめて報告する

# 報告の形
- できたもの / 確認してほしい点 / 次の一手
06

エージェントで、別の目を入れる。

Claude Codeでは、別の文脈で動く担当（サブエージェント）を作れます。作った過程を知らない担当に成果物だけを見せると、自分で自分を採点する状態を避けられます。

.claude/agents/reviewer.md（ひな形）
---
name: reviewer
description: 成果物ができたら必ず使う検証役。作った過程は見ずに、成果物だけを見て合否を出す。
tools: Read, Grep, Glob
---

あなたは検証担当です。渡された成果物だけを読み、
1. 依頼の条件を満たしているか
2. 事実や数字に根拠があるか
3. 個人情報や秘密の情報が入っていないか
を確かめ、「合格」か「差し戻し（理由つき）」で答えてください。
  • 置き場所： このプロジェクトだけなら .claude/agents/、全プロジェクトなら ~/.claude/agents/ です。
  • tools： 読むだけの道具に絞ると、検証役が勝手にファイルを書き換えません。
  • 本文： その担当への指示になります。役割と、答え方の形を書きます。
GUIDE · BUILDClaudeアプリだけで使う場合は、検証役を「スキル」として作り、司令塔から呼ぶ形でも同じ考え方を取り入れられます。
07

守りのルールを、最初から入れておく。

AIの組織が動き出すほど、事故が起きたときの影響も大きくなります。社訓（個人の設定）に安全のルールを書いておけば、どの会話でも守られます。

個人の設定に書く文
システム開発やコードを作るときは毎回、OWASP Top 10、認証と認可、入力のチェック、パスワードやAPIキーなど秘密情報の扱いを確認してから進めてください。
やってはいけないAPIキーやパスワードをSKILL.mdや会話に書かないこと。外から取り込むスキルは、中身を読んで危ないコマンドがないか確かめてから入れること。
08

使うたびに、組織を育てる。

スキルは一度作って終わりではありません。仕事が終わるたびに振り返り、マニュアルに戻していくと、どんどん自分の会社らしくなります。

仕事の終わりに送る文
今回の作業をふり返って、使ったスキルに足すべきこと・消すべきことを教えてください。直した版のSKILL.mdも出してください。
  • 効果を記録する： 「何分かかっていた仕事が何分になったか」をメモしておくと、次にどこを任せるかが決めやすくなります。
  • 入口は1つに： スキルが増えてきたら、「作って」で動く司令塔を1つに決めて、他はそこから呼ぶ形にまとめます。
  • 似たスキルはまとめる： 説明が近いスキルが2つあると、どちらが動くかがぶれます。
Q&A

つまずきやすいところ。

スキルを作ったのに使われません

description が短すぎることが多いです。「何をするスキルか」に加えて、「記事にして」「まとめて」のような自分の頼み方を入れてみてください。Claude Codeなら /スキル名 で直接呼ぶこともできます。

毎回、出力の形がばらばらです

SKILL.md に「出力」の項目を作り、見出しや順番を決めて書いてください。良かった出力をそのまま例として貼っておくのも効果的です。

スキルはいくつ作ればいいですか

最初は3つで十分です。おすすめは、自分の文体のスキル、いちばん困っている仕事のスキル、検証役のスキルです。数より、毎週使うことのほうが大切です。

プログラミングができなくても作れますか

作れます。SKILL.md はふつうの文章で書けますし、このページの指示文のようにClaudeに書いてもらうこともできます。エージェント（ステップ6）だけはClaude Codeが必要です。

人のスキルを使ってもいいですか

公開されているものは使えますが、ライセンスと中身を必ず確かめてください。知らない外部サイトにデータを送る処理や、ファイルを消すコマンドが入っていないかを見ます。
